    Detection rules — layer 1

    Contacting the rules engine…

      Pattern rules (new level crossing, rate spike, write outside the pattern) stay silent until a baseline seals — about 150 packets into a feed, or immediately when the store already holds history. Absolute rules (new device, IT-to-controller, non-HMI write, threat intel) fire from the first packet. Alerts appear in the Events log and flash on the map.

      Early warning — layer 2 (statistical)

      Contacting the anomaly layer…

        How it works: traffic is scored in 30-second chunks against a learned baseline — who talks to whom, which commands each device uses, who writes, how much traffic is normal. Odd chunks raise the risk score with the reasons listed; at 50+ an early-warning alert fires. It exists to catch the snooping phase, before anything destructive happens. While it says "learning", alerts are held back on purpose.

        Attack scenarios — lab only

        One-click attack scripts, modeled on public reporting, run against the simulated plant only. Start the simulation first and let it run a minute so the baseline exists — then fire one and watch the Events log and map. Every scenario should be caught; normal traffic should never be.
