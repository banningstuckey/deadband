    Detection rules — layer 1

    Contacting the rules engine…

      Pattern rules (new level crossing, rate spike, write outside the pattern) stay silent until a baseline seals — about 150 packets into a feed, or immediately when the store already holds history. Absolute rules (new device, IT-to-controller, non-HMI write, threat intel) fire from the first packet. Alerts appear in the Events log and flash on the map.

      Early warning — layer 2 (statistical)

      Contacting the anomaly layer…

        How it works: traffic is scored in 30-second chunks against a learned baseline — who talks to whom, which commands each device uses, who writes, how much traffic is normal. Odd chunks raise the risk score with the reasons listed; at 50+ an early-warning alert fires. It exists to catch the snooping phase, before anything destructive happens. While it says "learning", alerts are held back on purpose.

        Local AI (Ollama)

        Checking for a local model…

        The analyst and the plain-English log query both run on a model on this machine, through Ollama — nothing is sent anywhere. Ollama is a separate app Deadband can't bundle (it's ~1 GB plus several GB per model, with its own installer), so it installs once, outside Deadband:

        1. Download and install it from ollama.com/download (macOS, Windows, or Linux).
        2. In a terminal, pull a model: ollama pull llama3 — the small general model Deadband is tuned for.
        3. Come back here and hit Recheck. Ollama starts itself on login; Deadband finds it at 127.0.0.1:11434.

        Deadband works fully without it — the analyst and the AI query toggle just stay quiet until a model is there. Full steps live in docs/setup-ai.md in the repo.

        Checking what's stored…

        Events are stored in a SQLite file in the app's data directory on this machine — plant data never leaves it. Clearing wipes devices, connections, and events; every baseline relearns from zero, which is handy in the lab and a real decision in the field.
